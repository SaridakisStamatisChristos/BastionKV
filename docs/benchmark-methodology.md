# Reproducible performance calibration

`python3 scripts/bench.py --n 1000 --runs 3 --output evidence/benchmarks` builds the optimized benchmark binary, runs fresh per-run databases, and preserves every latency sample as CSV plus environment (compiler, CPU, filesystem, OS, time, SQLite version). Run from a clean target if changing toolchains produces multiple benchmark binaries. No timings are generated during ordinary unit tests.

Workloads: sequential and permuted random synchronous writes; random reads; deterministic 90%-read and 90%-write mixed workloads; 32-key range scans; atomic transaction batches 1/8/32/128; five full compactions; ten post-checkpoint opens; ten WAL-history recoveries. Keys u64 big-endian (8 bytes), values 128 bytes. Batches repeat configured keys, with one sync per transaction. Group latency per transaction is preserved; throughput counts logical key operations, with scans/compactions/opens counted as one operation each. Compaction throughput in bytes/sec can be computed as live_payload_bytes divided by latency. Neither clone overhead nor checksum/sync cost is omitted from measured API call latency. Setup/prefill is explicitly outside measured phases.

Raw records report workload/sample/logical_operations/latency_ns; summaries report operations/s, median, p95 and p99 (nearest rank). Metrics preserve WAL bytes appended before compaction, checkpoint bytes written, before/after storage bytes, and compacted storage amplification relative to logical payload (keys+values). WAL/checkpoint bytes exclude initialization, metadata replacements and filesystem block/journal overhead: they are format-byte counters, not device physical-write measurements. Reopen and WAL-recovery phases are separate. Benchmark run fails on state mismatch.

Optional baseline is automatic when Python stdlib SQLite is available: single-key sequential writes only, identical keys/values, one transaction per call, SQLite DELETE journal and synchronous=FULL. Same host/temp filesystem, fresh schema/database; raw timing plus count verification preserved. SQL/B-tree/index costs and different commit protocols are real implementation differences; no other workload has an external baseline, and no speedup claim is made from these samples. Calibration cannot prove comparable device power-loss behavior. Filesystem page cache isn't cleared; reopen results are warm-cache measurements.
